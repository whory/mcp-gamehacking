# Frida

Cross-platform dynamic instrumentation toolkit widely used on Android/iOS (and desktop) to attach/spawn processes, intercept native/Java/ObjC APIs, and script runtime behavior without static patching. For mobile game-security routing (package/platform vs engine vs kernel lanes), see [[overviews/mobile-security]] topic-routing table.

## Observation limits

Frida distinguishes **injected**, **embedded**, and **preloaded** operation—these are integration modes, not universal stealth levels or guarantees of early-execution coverage. Bind a report to the exact tool revision, target build, entry point, required privilege, and actual evidence source. **Embedded Frida Gum** inside LSPosed modules such as [[com-fuck-iab]] (FKIAB; native C++ layer runs compiled TypeScript scripts per target package for multi-store IAP billing hooks) illustrates in-process embedded instrumentation without external `frida-server` attach.

| Question | Evidence to preserve |
|----------|---------------------|
| What boundary was crossed? | Owned debug integration vs user-space process access vs privileged/kernel component |
| What changed in the observation? | Module/memory provenance, process lifecycle, control-channel exposure, instrumentation logs |
| What could be missed? | Uncovered startup periods, native vs managed execution, unloaded components, observer effects |
| Is a detector conclusion justified? | Defined observable signal, exact tested configuration, benign/debug-build comparison, FPR/FNR limits |

Packing components into one binary, moving work to a different layer, or changing instrumentation mode does not establish fewer observable artifacts, universal compatibility, or guaranteed nondetection. Evaluate the complete privileged path and its management interface. Pair with [[mobile-trust-boundaries]] and [[mobile-anti-cheat]] detection-finding review.

## Game-security uses

Hook game/[[il2cpp]] natives, bypass SSL pinning, probe root/jailbreak checks, trace anti-cheat detectors. Self-hosted mobile pentest dashboards such as [[rootraven]] (Kakaxh1; Flask web UI; ADB + Frida + JADX + Burp + logcat; pre-built hooks for SSL pinning, root/jailbreak bypass, anti-debug, biometrics, and crypto sniffing; manifest/SharedPreferences/deep-link/MASVS modules) consolidate common Frida scripting into a browser command center for game client and anti-cheat assessment. Browser-based [[frida-ide]] (MrOplus; Python/FastAPI + React/Monaco; device/process management, spawn/attach controls, one-click `frida-server` install, APK pull + apktool/[[jadx]] decompilation, SSL pinning/root/trace/crypto snippets, Claude Code hook extraction from decompiled projects, codeshare.frida.re import) targets the same unified Android instrumentation workspace for game security analysts. VS Code extension [[vscode-frida]] (ChiChou; unofficial Frida workbench; TypeScript + Python; target selection, script editing/dispatch, REPL, device logs, iOS/Android helper tooling; `frida-tools` integration) offers editor-native mobile instrumentation beside [[frida-ide]]. Web dashboard [[grapefruit]] (ChiChou; TypeScript; Frida runtime exploration; method/crypto hooks, filesystem/SQLite inspection, log streaming, crash reporting, keychain/keystore, traffic capture, Java/ObjC introspection, environment manipulation; iOS + Android) consolidates interactive mobile pentest workflows in a browser UI beside [[frida-ide]] and [[vscode-frida]]. iOS IPA decrypt/dump CLI [[bagbak]] (ChiChou; Node.js/TypeScript; Frida agent for runtime decryption; app extensions and embedded frameworks; USB and remote jailbroken devices; deprecated; `bagbak@5` needs Frida 17) targets jailbroken iOS app acquisition before static RE. [[mast-orchestrator]] (GliTcHZzZ67; Flask web dashboard; ADB root checks, one-click `frida-server` deploy, built-in SSL pinning/root/crypto hooks, whitelisted remote script sources, live hook streaming, token-auth API) offers a lighter MAST-focused orchestration surface beside [[rootraven]] and [[frida-ide]]. Desktop terminal orchestrator [[moabille]] (jafarm189; Python TUI; simultaneous multi-device Android/iOS; dual-pane file transfer; scrcpy mirror; automated Frida + Objection setup; ADB/iproxy/ioscpy; arrow-key navigation) consolidates adb/scrcpy/iproxy mobile pentest workflows in a shell UI beside browser dashboards. On Android native libraries stacked with VMProtect and OLLVM, [[frida-vmp-bypass]] (tomhamidi97-arch) uses spawn-mode **boundary hooks** on libc/JNI/Java exits to log side effects with caller addresses inside the protected `.so`, cross-reference with IDA, and tamper args/returns once detection sites are mapped—avoiding full static CFF or VM bytecode recovery. For pinpointing the first conditional branch where two native runs diverge—license checks, anti-cheat heuristics, or [[control-flow-flattening]]-flattened paths—[[veridiff]] (Veridiff; Python + Rust; Stalker dual-trace + longest-common-prefix basic-block diff + Capstone disassembly; OLLVM CFF resync; x86/ARM64) scales beyond manual disassembly trace comparison. APK triage CLI [[nightowl]] profiles RASP/Frida-detection stacks (RootBeer, SafetyNet, hooking checks) and can emit tailored bypass scripts per profile for mobile assessment workflows. Static-analysis generators such as [[auto-generate-frida-bypass-scripts-for-ssl-pinning-root-detection-on-android-ios]] scan APK/IPA binary signatures (OkHttp, TrustKit, Flutter, gRPC; RootBeer, Play Integrity, commercial SDKs) and emit targeted Frida hooks for SSL pinning and root/jailbreak bypass without manual class hunting. Mobile ACs often ship Frida/ Magisk detection; hide stacks (DenyList/Shamiko, KernelSU isolation) appear in the same research space. Defensive Detection:Frida samples such as [[antifrida]] and hooking-oriented [[frida-detection]] (Java/C++; muellerberndt) sit on the AC side of that lane. Write-up collections such as [[anti-frida]] (apkunpacker; libc prologue integrity checks before/after hook interception; JS script examples for commonly hooked functions) document instruction-level hook detection patterns. Native Android counterpart [[detect-frida]] (darvincisec) adds named-pipe scans, Frida thread-name checks, `.text` memory-vs-disk ELF integrity, plus syscall-based libc replacement and O-LLVM hardening against hooking. Offensive counter-scripts such as [[anti-frida-bypass]] (apkunpacker; Frida JS; libc/process-introspection hooks; procfs string masking; multiple variants for app-specific anti-instrumentation) help researchers stress-test those detectors. Broader Android bypass technique collections such as [[frida-detection-bypass]] (aimardcr; debugger checks, default-port and protocol fingerprinting, memory artifact scans; JS hooks + CLI configs + native JNI; non-gadget-only injection workflows) extend that lane. Layered RASP-focused script [[ultimate-frida-bypass]] (Ishanoshada; nineteen Java/native hooks; Talsec/freeRASP/PairIP neutralization; port/netstat Frida detection, threat callbacks, SSL pinning, Crashlytics suppression, libc native scans) targets Talsec demo and similar protected Android apps. Source-level Android patch/build automation via [[florida]] (Ylarod; anti-detection `frida-server`; string/symbol/artifact renaming; scripted reproducible builds) reduces recognizable Frida fingerprints before deployment. Build-from-source stealth servers such as [[phantom-frida]] (TheQmaks; Python patch scripts + name generators; randomized strings/symbols/artifacts at compile time; WSL build; JavaScript tests) sit in the same anti-detection lane. [[strongr-frida-android]] (CrackerCat; upstream-tracking Android `frida-server` patch automation; core patches to strings, pipes, symbols, and protocol behaviors; lightweight patch-workflow repo) complements that lane when analysts need reproducible anti-detection builds against blocked Frida signatures. Android fingerprint-reduction patch set [[frida-stealth]] (AsenOsen; default ports, socket names, thread names, loop labels, and related `frida-core`/`frida-gum` markers; patch files + build instructions for custom instrumented binaries) sits in the same anti-detection lane. CI polymorphic arm64 builds via [[morphida]] (1013503897; clone upstream Frida tag per build; randomized process/memfd/thread/path strings; NDK `llvm-strip` of `gum_*`/`frida_*` symbols; CI strings gate; adb helper scripts) produce per-release static fingerprints without vendoring Frida sources. Stealth mobile Frida deployments (hex-replace of server strings/symbols/artifacts; rooted and rootless iOS install scripts) use [[fridare]]. Boot-persistent anti-detection server modules such as [[florida-zygisk]] (Magisk/KernelSU/APatch; Ylarod-patched Florida `frida-server`; random port; magisk-frida-derived) auto-start hardened Frida on device boot for dynamic analysis against anti-Frida checks. Magisk boot modules such as [[magisk-hluda]] (Exo1i; stealth-modified `frida-server` at boot; module lifecycle scripts + C++ update/download helper; HTML/JS WebUI for start/stop/status/custom params; persistent mobile RE with reduced detection) offer a similar boot-time server lane. Zygisk gadget injectors such as [[zygisk-frida]] load the in-process Frida agent via Magisk Zygisk into app processes during specialization for early hooking without external attach. Anti-detection Zygisk gadget modules such as [[ksurusda]] (zensu357; Rusda-patched Frida kernel; `postAppSpecialize` inject; library remapping, startup delay, child-process gating; WebUI/JSON config; TCP listen + offline script modes; KernelSU/Magisk/APatch) load stealth in-process agents without APK resigning. KernelSU server modules such as [[frida-rs]] (MiChongs; official `frida-server` packaged as installable module; Rust supervisor `frida-ksud` for lifecycle/crash recovery; Material 3 WebUI; multi-ABI builds; loopback default + token for non-local TCP) supervise stock Frida server deployment on rooted Android. Script collections such as [[frida-scripts]] (smartdone; JS/Python; editor tooling and hooking) and [[0xdea-frida-scripts]] (0xdea; iOS/Android/Linux tracing, class discovery, bypass-oriented snippets) sit in the same cheat / Frida research lane. Universal Android root-detection and SSL-pinning bypass script [[ssl-bypass]] (0xCD4; Frida JS; Java and native library hooks; no app-specific customization; authorized mobile pentest) complements signature-driven generators such as [[auto-generate-frida-bypass-scripts-for-ssl-pinning-root-detection-on-android-ios]] with a one-script drop-in workflow. Organized Android script kit [[frida-mobile-kit]] (unrandoms; categorized Frida JS for certificate pinning bypass OkHttp/TrustManager/Conscrypt/Flutter/React Native, HTTP/WebSocket traffic and crypto key logging, root/SafetyNet bypass, method tracing and string dumps; Python CLI for list/spawn/attach/combine hooks and file output) targets protected Android apps and games with anti-tamper, SSL pinning, and integrity checks. Dynamic root-detection **tracing** via [[root-detection-low-level]] (3v1lC0d3; Frida JS; hooks `java.io.File` and `Runtime.exec`; keyword path filters for `su`/`bin`/`apk`; logs shell commands + Java stack traces on suspicious FS access; malware/AC root-check RE—not a bypass drop-in) helps analysts map which code triggers low-level runtime checks. Cross-platform game/app hook libraries such as [[fridascript]] (gmh5225; JavaScript call intercept, API trace, runtime modify; Android/iOS/desktop; iOS low-level scripting) complement that lane. Python hook-maintenance helpers such as [[hook-updater]] automate refreshing Frida hook scripts when targets change. Class/function-trace and return-value-modify helpers such as [[frida-android-hook]] (iOS-oriented scripts noted) sit in that same lane. Stack/backtrace helpers such as [[frida-stack]] reuse unwind helpers for clearer Frida traces. Unreal explorers also script Frida dumpers in TypeScript (e.g. [[ts-ue4dumper]], with C++ offset helpers) or as standalone Frida scripts such as [[frida-ue4dump]] (Android UE4 reflection hook; `UObject` enum / property offsets / SDK headers at runtime). For Unity IL2CPP dumps across a wide version range, [[frida-il2cpp-bridge]] is a common Frida-side bridge. Terraria **Android** IL2CPP mod-menu skill packages such as [[terraria-android-modding]] (abcd123rft; Frida + JsHook JavaScript; il2cpp-by-name per-frame `Player` hooks; native system-UI overlay menus; Python offline APK/icon tooling; cheat / Frida) illustrate documented JsHook injection beside bridge-based TypeScript mod menus. On Windows desktop, [[thats-no-pipe]] uses Frida to intercept named-pipe I/O (`NtReadFile`/`NtWriteFile` and related waits) and relay IPC to an HTTP proxy over WebSocket for protocol analysis and fuzzing. On macOS, [[frida-usb-dump]] sniffs and dumps USB traffic (Big Sur-era offsets). On iOS and macOS, [[xpc-tracer]] traces XPC IPC messages (xpcspy variant). On Android ARM64, [[rust-frida]] offers a Frida-like injector/agent stack (QuickJS, Java/native/stealth hooks, QBDI) that pairs with [[mkpms]] wxshadow KPM stealth (R^X page-split hook; bypass self-read integrity). Hardware data watchpoints via Frida's `setHardwareWatchpoint` — what-writes/accesses tracing without software breakpoints — are documented in [[frida-watchpoint-tutorial]] (trial-and-error walkthrough; cheat / Frida). Runtime JNI native-method discovery — mapping Java `native` stubs to loaded `.so` symbols via hooking and memory analysis — is supported by [[frida-find-jni-native-methods]] (JavaScript; cheat / Frida). Android **seccomp**-backed SVC/syscall tracing via [[frida-seccomp]] (Abbbbb; Frida JS + Python orchestration; seccomp trap handling; SVC capture with stack traces and register args/returns; multi-process logging; linker symbol inspection + Frida CModule redirect/replay from a controlled thread; mobile RE / game-security syscall visibility) complements JNI/native hooks when analysts need kernel-interface visibility below libc. Static+dynamic RE bridge via [[frinet]] (IDA Pro plugin; run Frida on a live target while navigating corresponding code in IDA; sync runtime memory values, function args, and return values into the static analysis view) complements standalone Frida scripting for combined workflows. Binary Ninja-side counterpart [[frinja]] (Frida plugin for Binary Ninja; continuation of BinRida; dzervas) bridges the same static+dynamic workflow inside BN. Ghidra-side counterpart [[dragonhook]] exposes Ghidra database functions, comments, and xrefs to Frida agents via localhost HTTP API with in-Ghidra session GUI (runtime indirect-call resolution, live xref/comment updates, symbol backtraces, call tracing; mitros123). Hook-script codegen from disassembly context via [[ghidra-frida-hook-gen]] (CENSUS; Java Ghidra extension; right-click full script generation, reusable snippets, advanced hook config; function-level and arbitrary address hooks; static→dynamic setup accelerator) complements that live-bridge lane. Cheat Engine remote memory via [[frida-ceserver]] implements the ceserver protocol through Frida attach on mobile and desktop (non-rooted Android supported where Frida can attach). Beginner streamed DBI workshops such as [[frida-boot]] (gmh5225; YouTube; binary instrumentation fundamentals for cheat / Frida newcomers) complement targeted tutorials like [[frida-watchpoint-tutorial]].
